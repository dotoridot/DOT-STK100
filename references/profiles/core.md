# Core: 기술 문서 작성과 교정

SKILL.md의 공통 보존 원칙을 적용하고 문서의 독자와 목적을 확인한다. 실제 원문이 있으면 rewrite, 새 문서를 작성하면 explain을 사용한다. 요청된 범위에서 판단하며 원문에 없는 사실을 본문에 섞지 않는다.

1. 코드, API, 수치, 단위, 조건, 예외, 부정, 규범 강도와 근거 상태를 확인한다.
2. 조건-행동-결과를 연결하고 반복 용어를 통일한다. 관리 대상 표현은 용어집의 해당 정의, 예시와 예외를 확인해 의미가 같은 경우에만 통일한다. 일부 부정, 조사 만/도, 은/는의 대조와 범위를 유지한다.
3. 알려진 동작은 구체적인 동사로 적는다. 일반 표현은 권장 표현 사전의 조건을 확인해 익숙한 말과 직접적인 동사로 다듬고 전문 용어는 유지한다. 명사형과 피동형은 불필요한 경우에만 바꾸고, 주체나 순서를 추측하지 않는다.
4. 문장 분리 후 뒤 문장에도 원래 조건과 예외가 적용되는지 대조한다. 순서를 모르는 병렬 행동에는 번호로 선후를 만들지 않는다.
5. 원문의 주장 누락과 수정문의 추가 주장을 각각 검토한다. 사실 오류 의심은 verify 제안으로 분리한다.

모호성이 판단을 바꾸면 needs_context로 남긴다. 원문이나 비교 문서가 없는 새 설명은 원문 대비 의미 보존 검토 완료라고 표시하지 않는다. 필요한 규칙의 예외만 rules/rules.json에서 찾아 읽는다.
