# Audit: 원문 대비 의미 변경 위험 검토

원문과 수정문을 함께 확보하고 rules/rules.json을 읽는다. 기본 작업은 review이며 사용자가 교정까지 요청한 경우에만 rewrite 결과를 별도로 제시한다. 수정문이 없으면 원문 자체의 모호성을 검토하고 비교 검사는 미실행으로 기록한다.

원문 주장마다 대응 구절과 다음을 대조한다: 주체/대상, 조사/초점, 조건 범위, 수량/부정/논리, 값/단위/경계, 시간/순서/인과, 규범/가능성, 예외/위험, 출처/관찰 범위, 보호 구간.

특히 같은 숫자나 식별자가 남아 있어도 연결된 대상이 바뀌었는지 확인한다. `할 수 있다`를 능력/허용/가능성 중 하나로 임의 확정하지 않는다. 동작의 생략과 실패를 구분한다.

발견 사항에는 규칙 ID, 원문과 수정문 구절, 위험, 증거 상태, 판정 이유, 필요한 문맥을 남긴다. 판정은 compatible/meaning_changed/needs_context를 사용한다. Linter의 candidate를 confirmed로 자동 승격하지 않는다. 주장 대응표는 검토 산출물이며 비공개 내부 추론을 출력하는 형식이 아니다.

독립 사람 검토 전에는 `Audit 보조 검토, 독립 사람 검토 미완료`로 보고한다. 검토자, 규격 버전, 입력 해시, 검토 범위와 남은 미확인을 기록한다. 파일 로드, 구조 테스트, AI 자기 검토만으로 Audit 완료를 선언하지 않는다.
