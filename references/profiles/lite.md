# Lite: 빠른 기술 설명

질문에 대한 결론을 먼저 쓰고 필요한 원리, 조건과 예외만 이어서 설명한다. 모든 답변에 제목이나 고정 목차를 붙이지 않는다. 기술 독자의 수준을 유지한다.

- 사실과 추정, 예시를 구분한다. 원문이나 출처가 없으면 특정 API 동작을 만들어 설명하지 않는다.
- 수치, 식별자, 부정, 조건, 예외와 가능성은 간결함보다 우선한다.
- 한 문장 한 동작은 권장이다. 문장을 나누면 조건이 어느 결과에 적용되는지 다시 확인한다.
- 한국어에서는 문맥으로 주체가 분명하면 생략할 수 있다. 미상인 주체를 채우려고 피동형을 무조건 능동형으로 바꾸지 않는다.
- 같은 개념에는 같은 용어를 쓴다. 서로 다른 개념을 한 단어로 합치지 않는다.

ASD-STE100의 명확성 설계를 참고한 독립 한국어 원칙이다. 영어 통제 어휘, 품사 규칙과 단어 수 제한을 그대로 적용하지 않는다. 검증이 필요한 설명은 Core 또는 Audit으로 확대하고 필요한 근거만 추가 확인한다.
