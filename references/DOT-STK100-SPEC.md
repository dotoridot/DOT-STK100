# DOT-STK100 — DOT Simplified Technical Korean

**한국어 기술 설명의 의미 보존·명료성·근거 관리를 위한 독립 작성 규격**

버전: `0.2.0-draft.4` · 작성일: 2026-11-09 · 저작자: **dotoridot** · 기획·관리: **dotoridot**

## 1. 지위와 범위

DOT-STK100은 개인 프로젝트의 공개 규격 초안이다. 공인 표준, 인증 제도, ASD-STE100의 공식 한국어판이 아니다. `100`은 프로젝트 식별자이며 규칙 수·점수·품질 보증 비율을 뜻하지 않는다.

기술 설명, SDK/API 문서, 코드 리뷰, 장애 보고서, 운영 절차를 대상으로 한다. 문학·광고·개인적인 말투의 글을 강제로 단순화하지 않는다. 이 규격은 사실 검색기나 의미 동치 증명기가 아니다.

통제 언어 연구와 기술 문서 작성 접근에서 출발하되, 규칙·용어 정의·예시는 이 프로젝트를 위해 독립 작성한다. 선행 자료의 원문 규칙·사전·표를 번역해 옮기지 않는다. 연구 근거와 적용 한계는 [연구 검토](RESEARCH.md)를 따른다.

## 2. 가장 중요한 구분

**표현을 바꾸는 일과 사실을 고치는 일은 다르다.**

| 모드 | 기본 입력 | 해야 할 일 | 하지 않을 일 |
|---|---|---|---|
| `rewrite` | 원문·대상 독자, 선택적 문맥 | 의미를 유지하며 표현 편집 | 미확인 사실을 보완하거나 원문 오류를 조용히 수정 |
| `review` | 원문, 선택적 수정문 | 위험 구절·규칙·근거·수정 후보 보고 | 검토만 요청받고 문서를 덮어쓰기 |
| `verify` | 주장과 검증 가능한 자료 | 근거와 반례를 확인하고 사실 수정안을 분리 | 출처 확인을 직접 실험으로 표시 |
| `explain` | 질문·자료·독자 | 출처의 범위 안에서 새 설명 구성 | 없는 사실·원인·API 동작을 생성 |

rewrite에서 사실 오류가 의심되면 해당 부분을 미확인 상태로 유지하거나 편집을 보류한다. 확인된 오류는 별도 검토란에 표시한다. 이미 틀린 문장을 새 사실처럼 재배포하도록 권장하지 않는다. 현재 요청에서 사실 수정까지 허용한 경우 근거를 밝혀 그 범위에서 적용한다. rewrite만 요청한 경우 사실 수정안을 분리한다. 이미 받은 권한을 반복해서 요청하지 않는다.

## 3. 보존해야 할 의미

원문과 수정문 사이에서 다음 항목을 확인한다. 해당 항목이 없으면 `not_applicable`, 뜻을 알 수 없으면 `unknown`으로 남긴다. 미상을 임의로 채우지 않는다.

| 축 | 확인 질문 |
|---|---|
| 주체·대상·행동 | 누가 무엇에 어떤 행동을 하는가? |
| 조건·적용 범위 | 어떤 조건이 어느 행동과 결과에 적용되는가? |
| 부정·수량·논리 | 부정의 대상은 무엇인가? 일부인가 모두인가? AND인가 OR인가? |
| 값·단위·경계 | 값, 버전, 날짜, 비교 연산자와 포함 경계가 같은가? |
| 시간·상태·순서 | 실행 전·후, 진행·완료, 실패·미수행, 선후·동시성이 같은가? |
| 규범·가능성 | 해야 하는가, 권장하는가, 허용하는가, 가능성이 있는가? |
| 원인·근거·불확실성 | 관찰인가 추론인가? 원인이 확정됐는가? |
| 예외·위험·보호 구간 | 예외, 경고, 코드, 식별자, 인용이 그대로 남는가? |

주장표는 검토 보조물이다. 작성한 주장표 자체가 틀릴 수 있으므로 원문과 함께 검토한다.

## 4. 규칙 강도와 프로필

`MUST`는 해당 작업과 관련될 때 지켜야 하는 프로젝트 요구다. `SHOULD`는 명시적인 이유로 예외를 허용하는 권장이다. 이것은 이 프로젝트의 정의이며 외부 인증 기준이 아니다.

- **Lite**: 일상 기술 설명. 의미·근거·기밀 관련 MUST는 생략하지 않는다. 불필요한 제목·라벨만 줄인다.
- **Core**: 개발 문서. 관련 MUST와 용어 정의를 확인하고 미확인 사항을 남긴다.
- **Audit**: 보안·운영 절차. Core에 원문-수정문 대응, 출처·실행 범위 기록, 독립 사람 검토를 더한다.

프로필은 검토 깊이의 차이다. **80% 적용이라는 이유로 사실·조건·예외의 일부를 버릴 수 없다.**

## 6. 의미를 바꾸지 않는 조건 처리

다음은 가상 예시이며 실제 제품 사양이 아니다.

원문:

> 필수 권한이 없으면 SDK는 검사를 실행하지 않고 결과를 `NOT_EXECUTED`로 기록합니다.

위험한 교정:

> 필수 권한이 없으면 SDK는 검사를 실행하지 않습니다. SDK는 결과를 `NOT_EXECUTED`로 기록합니다.

두 번째 문장이 항상 실행되는 것처럼 읽힐 수 있다. 안전한 대안은 다음과 같다.

> 필수 권한이 없으면 SDK는 다음과 같이 처리합니다.
> - 검사를 실행하지 않습니다.
> - 결과를 `NOT_EXECUTED`로 기록합니다.

목록은 선후 관계를 추가하지 않는다. 원문에 주체가 없었다면 SDK라는 주체를 새로 넣지 않는다.

## 7. 한국어 편집에서 금지하지 않을 표현

`것`, `수`, `관련`, `해당`, `되다`, `수행`, 피동형은 그 자체로 위반이 아니다. 문맥상 역할이 불필요한 경우에만 바꾼다.

`실행될 수 있습니다`를 `실행됩니다`로 바꾸면 가능성이 확정으로 변할 수 있다. `모두 성공하지는 않습니다`를 `모두 실패합니다`로 바꾸면 부분 부정이 전체 부정으로 변한다. `클라이언트가 서버를 확인합니다`에서 조사를 바꾸면 주체와 대상이 달라질 수 있다.

전문 용어는 읽기 난도만으로 제거하지 않는다. 낯설면 짧은 정의를 덧붙인다. 단, rewrite에서 새 정의가 원문에 없으면 본문에 섞지 말고 추가 설명으로 구분한다.

## 8. 근거 상태

| 상태 | 의미 | 표시 예 |
|---|---|---|
| `documented` | 지정한 문서에서 해당 주장을 확인 | 문서 확인: 버전과 해당 절 명시 |
| `observed` | 제공된 테스트·로그의 한정된 범위에서 관찰 | 관찰: 환경·절차·결과 명시 |
| `inferred` | 근거를 바탕으로 한 추론 | 추정: 이유와 대안 설명 |
| `unverified` | 자료가 없거나 충돌해 확인하지 못함 | 확인 필요: 필요한 자료 명시 |
| `synthetic` | 설명·시험을 위한 가상 자료 | 가상 예시: 실제 제품 사양 아님 |

원문에 출처가 있다고 해서 그 링크를 직접 확인한 것은 아니다. 읽지 않은 자료는 확인했다고 쓰지 않는다. 출처 간 충돌은 감추지 않는다. 원문 자료의 미확인과 프로젝트의 설계 가정을 구별한다.

## 9. 검토 판정

검토 결과에는 두 축을 함께 기록한다.

**의미 판정**: `compatible`(제공된 범위에서 보존 확인), `meaning_changed`(구체적인 변경 확인), `needs_context`(판단 자료 부족).

**발견 사항의 심각도**: `BLOCKER`(의미 손실·허위 사실/실행·기밀 위험), `ERROR`(해당 MUST 위반 확인), `WARN`(명료성 개선 후보).

의심과 확정은 다르다. 숫자 문자열이 달라졌다는 정적 경고만으로 의미 변경을 확정하지 않는다. 반대로 문자열이 같아도 주체·조건·논리가 바뀔 수 있다. `needs_context`는 합격이 아니다.

`Core 검토 완료`라고 표시하려면 적용 규격 버전, 원문/수정문 식별자, 검토자, 검토 범위, 남은 미확인 사항을 기록한다. 인증 배지나 100점 보증으로 표현하지 않는다. Audit에서 독립 검토가 빠졌으면 Audit 완료로 표시하지 않는다.

## 10. 길이와 점수의 처리

v0.1의 지시문 15어절·설명문 20어절은 실험 후보일 뿐이다. v0.2 기본값에서는 자동 길이 경고를 끈다. 켤 경우 어절 계수기·예외 구간·임계값을 기록한다. 길이 경고는 실패 조건이 아니다.

간결성·가독성 점수가 높아도 의미 손실을 상쇄할 수 없다. SARI·LENS·문장 임베딩 유사도·LLM 평점 중 어느 것도 단독 합격 판정기로 사용하지 않는다. 자세한 평가 설계는 [평가 계획](../docs/EVALUATION.md)을 따른다.

## 11. 변경과 검토 기록

규칙 ID는 재사용하지 않는다. 의미가 달라지는 규칙 변경에는 이유·반례·영향·회귀 사례를 추가한다. 생성 표와 규칙 파일을 함께 검사한다. v0.x 변경도 버전과 마이그레이션 설명을 남긴다.

이 문서의 규칙은 **독립 설계 제안**이다. 실제 이해도 향상·오류 감소·한국어 분야별 최적 길이를 검증한 결과는 아직 없다.

## 12. 보고 전용 자동 검사의 위치

`scripts/lint_text.py`는 검토 후보만 보고한다. 규칙 위반의 자동 확정, 사실 판정과 의미 동치 증명은 제공하지 않는다. Lite/Core/Audit의 자료 로딩 경로는 SKILL.md를 따른다. 0.2.0-draft.3에서는 K03의 대조/한정 범위를 명시하고 M08의 사실 수정 권한을 현재 요청 기준으로 정리했다. 사례와 반례는 examples/BEFORE-AFTER.md 및 합성 평가 자료에 기록한다.

0.2.0-draft.4에서는 K07의 사람 사이 설명 문체와 P04의 명사구 제목을 보완했다. 예시와 예외는 [문체 예시](HUMAN-PROSE.md)를 따른다. 이는 문체 기본값이며 의미 보존이나 효과 검증의 강도를 바꾸지 않는다.
