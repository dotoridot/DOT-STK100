# 사람이 읽는 결과물의 문체 예시

규칙 기준은 YSK-K07과 YSK-P04다. 아래 자료는 가상 편집 예시이며 실제 제품 사양이나 문체 효과 검증 결과가 아니다.

## 제목

- 수정 전: `누구에게 필요한가요?`
- 수정 후: `주요 독자와 사용 상황`
- 수정 전: `어떻게 달라지나요?`
- 수정 후: `적용 전후 예시`

제목은 주제를 직접 드러낸다. FAQ에서 실제 질문을 제목으로 쓰거나 사용자가 대화체를 요청한 경우에는 질문형을 유지할 수 있다.

## 설명 본문

입력 사실: 취소한 요청은 재시도하지 않는다.

- 피할 예: `요청하신 대로 취소 예외를 반영해 쉽게 설명해 드리겠습니다.`
- 작성 예: `취소한 요청은 재시도하지 않습니다.`
- 사실 추가 위험: `저도 운영 중에 겪었는데, 취소한 요청은 재시도하지 않습니다.`

작성 예는 사실을 직접 설명한다. 사람 사이의 말투를 쓰더라도 제공되지 않은 경험과 감정을 추가하지 않는다.

## 절차와 인용의 예외

원문: `백업이 완료되면 설정을 변경하세요. 백업에 실패하면 설정을 변경하지 말고 담당자에게 알리세요.`

이 문장은 독자에게 실제 행동을 안내하므로 명령형을 유지한다. 설명형으로 바꾸면서 행동의 의무나 실패 조건을 약화하지 않는다. 인용문과 에이전트용 작업 지시문도 문체만을 이유로 일괄 변환하지 않는다.

## 문맥이 필요한 경우

`무엇이 달라졌나요?`라는 제목만으로는 일반 설명인지 FAQ인지 알 수 없다. 일반 설명이면 `변경 사항` 같은 제목이 가능하지만, 문서 종류와 사용자 요청을 확인하기 전에는 질문형이라는 이유만으로 위반을 확정하지 않는다.

rewrite에서 원문의 고유한 말투를 바꿔도 되는지 불명확하면 원문을 보존하고 확인할 사항을 남긴다. 새로 작성하는 설명과 말투 변경을 요청받은 문서에는 기본 문체를 적용한다.
