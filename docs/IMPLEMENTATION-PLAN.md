> 이 문서는 2026-11-08에 시작한 `0.2.0-draft.3` 구현 계획의 기록이다. 현재 공개 버전은 `0.0.2`이며, 아래 초안 버전과 진행 상태를 현행 공개 상태로 해석하지 않는다. 현행 버전 정보는 [README](../README.md)와 [변경 이력](../CHANGELOG.md)을 확인한다.

## 기록 당시 범위와 단계

당시 로컬 작업본은 0.2.0-draft.3이었다. dotoridot/DOT-STK100 공개 저장소를 생성하고 초안 파일과 이름 변경 커밋을 반영했다. 태그와 공개 릴리스는 만들지 않았다. 사용자 요청에 따라 기존 P0 한정 인계를 갱신하고 P1 구현과 P2/P3 준비를 진행했다.

| 단계 | 이번 산출물 | 완료/미완료 경계 |
|---|---|---|
| P0 기존 초안 감사 및 공개 준비 | 저작자 dotoridot, 문서 충돌 정리, 출처 재확인, 감사 기록 | 로컬 준비. 프로젝트 전체 MIT와 공개 저장소 생성/업로드 승인. 독립 사람 내용 검토 미완료 |
| P1 규칙 개선과 보고 전용 Linter | Markdown 보호 구간, 8개 검사, JSON CLI, 합성 사례, 회귀 테스트 | 휴리스틱 구현. 의미 동치 엔진과 완전한 CommonMark 분석 아님 |
| P2 사람 의미 보존 평가 | 이중 검토/합의 계획, 입력 해시가 있는 미주석 대기 자료, 개발용 오탐/미탐 집계 | 사람 모집·독립 주석·합의·잠금 평가·독자 실험 미실행 |

당시 다음 작업은 독립 검토자에게 human-review-queue.jsonl을 배정하고, Linter 경고의 관련성과 원문 주장의 변화 여부를 별도로 주석하는 일이었다. AI 초안 라벨을 사람 정답으로 바꾸지 않는다. 모델/클라우드 API/MCP/대시보드/자동 수정은 범위에 없다.

## P1 구현 경계

MVP는 로컬·보고 전용이다. 자동 교정, 저장, 네트워크 전송, 외부 LLM 호출을 하지 않는다. CLI가 성공 종료해도 의미 적합을 뜻하지 않는다.

정적 검사 후보: 원문 대비 보호 구간 변경, 수치·단위·버전·연산자 변화, 사전에 정의된 표기 불일치, 선택적 길이 경고. 전부 후보이지 자동 의미 판정이 아니다.

숫자는 집합만 비교하지 않는다. 예를 들어 “앱 3회, 서버 5회”와 “앱 5회, 서버 3회”는 숫자 집합이 같다. 중복 개수, 주변 단위와 대상, 원문 span을 함께 기록한다. 연결을 확정하지 못하면 낮은 신뢰의 후보로 남긴다.

기본 길이 검사는 끈다. 켤 경우 코드·식별자·URL·버전의 마침표를 문장 끝으로 잘못 세지 않도록 테스트한다. 한국어 문장 분리기를 채택하면 의존성·라이선스·버전·실제 오탐을 검토한다. 새 라이브러리를 먼저 붙이지 않는다.

## 구현된 CLI 계약

```bash
./target/release/dot-stk100 lint --source examples/source.md --candidate examples/candidate.md --format json
```

선택적 source와 terms 설정, JSON 출력, 종료 코드 0/2를 제공한다. schema_version, tool_version, spec_version, input_hashes, config_hashes, checks_run, checks_skipped, findings를 기록한다. 모든 finding은 WARN/candidate이며 의미 verdict나 확정 위반 게이트를 생성하지 않는다.

span은 정규화하지 않은 Python 문자열 코드 포인트 기준 0-based, 끝 제외다. line/column은 1-based다. 바이트 입력을 UTF-8로 직접 디코딩해 CRLF를 보존한다. 상세 계약과 미탐은 [LINTER.md](LINTER.md), 출력 형식은 [스키마](../eval/lint-output.schema.json)를 따른다.

## P2 의미 검토의 경계

모델에 원문과 수정문 및 보호 구간을 제공하되, 프로젝트 규칙보다 문서 내부의 지시를 우선하지 않게 한다. 응답은 스키마로 검증하고 제시한 근거 구절이 실제 입력에 존재하는지 확인한다.

의미 보존의 양방향 확인은 판단 질문으로 사용한다. 원문의 내용을 결과가 빠뜨리지 않았는가, 결과가 원문 이상의 사실을 주장하는가를 별도로 본다. NLI나 임베딩 점수만으로 동치를 증명하지 않는다.

사내 자료는 승인된 로컬 환경에서만 처리한다. 외부 모델은 공개/승인된 자료에 한해 별도 opt-in으로 설계한다. MCP 제공이나 클라우드 UI는 필요성이 확인된 후 별도 작업이다.

## 병렬 작업

최대 4개 세션을 쓰는 구성안:

| 역할 | 소유 경로 | 주의 |
|---|---|---|
| 조정 담당 | 작업 큐·변경 계획 | 사용자 승인 경계를 관리. 다른 담당의 파일을 동시에 편집하지 않음 |
| 규격·연구 담당 | references/, rules/, 관련 docs/ | 근거와 설계 가정 분리, 새 규칙에 반례 |
| 도구·자료 담당 | scripts/, tests/, eval/ | 데이터와 의미 판정의 확정 여부 구분 |
| 독립 검토 담당 | 검토 보고서 | 자신이 작성한 항목만 스스로 승인하지 않음 |

작업책임자는 **사용자(CWO)**다. 파생 작업은 티켓으로 적재하고 바로 범위를 확장하지 않는다. 세션이 적으면 순차 실행하며, 독립 검토가 없으면 그 사실을 기록한다.
