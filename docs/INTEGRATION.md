# korean-humanizer 및 에이전트 연계

## 입력 패키지의 연계 조사 기록

입력 패키지는 2026-11-08 연결된 GitHub로 공개 저장소 `dotoricode/korean-humanizer`의 `SKILL.md`와 `LICENSE`를 읽었다. SKILL.md는 내부 메모·기술 문서·법률 문서를 제외하고, 일반적으로 `## Humanized` / `## 주요 변경 (최대 5개)`의 출력 계약을 사용한다. LICENSE는 MIT다.

출처: [현재 SKILL.md](https://github.com/dotoridot/korean-humanizer/blob/main/SKILL.md), [현재 LICENSE](https://github.com/dotoridot/korean-humanizer/blob/main/LICENSE). main 링크는 변할 수 있으므로 실제 수정 전에 다시 확인한다. 이번 로컬 개선에서는 해당 원격 자료를 재확인하지 않았고 저장소를 변경하지 않았다. 이 절은 현재 계약의 독립 재검증이 아니다.

## 권장 라우팅

| 요청 | 도구 | 주의 |
|---|---|---|
| SDK 설명, 장애 분석, 기술 리뷰 | YUPK-STK100 | 의미·근거 보존 우선 |
| 뉴스레터, 마케팅, 일반 이메일의 자연스러운 말투 | korean-humanizer | 기존 적용 범위·출력 계약 유지 |
| 기술적 내용이 섞인 고객 이메일 | 명시적 모드 선택 또는 구간 분리 | 목적을 보고 선택. 두 스킬의 전역 후처리 금지 |
| 법률 문서 | 별도 도메인 절차 | 어느 스킬도 자동 일반화하지 않음 |

기술 문서 전체에 humanizer를 먼저/나중에 무조건 실행하지 않는다. 두 번째 교정에서도 조건·가능성·경고가 바뀔 수 있기 때문이다. 혼합 문서를 처리할 때는 기술 주장·코드·인용을 보호 구간으로 두고 최종 결과를 원문과 다시 비교한다.

## 독립 저장소

권장 경로는 `<실제 소유자>/yupk-stk100`이다. `<실제 소유자>`는 설명용 표기이며 실제로 존재하는 원격 URL이 아니다. 이 인계 패키지의 폴더명 `yupk-stk100`과 SKILL.md의 name을 일치시킨다.

스킬을 사용할 호스트가 읽을 수 있는 디렉터리에 **SKILL.md와 필요한 references/·rules/를 함께** 둔다. 특정 호스트의 설치 경로·자동 발견 규칙은 그 호스트 공식 문서와 실제 버전으로 확인한다. 이름만 복사하거나 SKILL.md만 떼어 설치해 참조를 깨뜨리지 않는다.

Agent Skills 형식 근거: [공식 명세](https://agentskills.io/specification). 호스트별 실행 테스트는 아직 하지 않았다.

## 기존 저장소에 보관해야 할 때

`extensions/yupk-stk100/` 등 독립 경로에 전체 패키지를 넣는 방안을 쓸 수 있다. 실제 레이아웃을 먼저 확인하고 기존 폴더를 덮어쓰지 않는다. 루트 SKILL.md, MCP 응답, 무료/유료 배포 경로는 별도의 변경 작업이다.

상위 저장소의 포괄적인 MIT 고지가 하위 문서의 제안 라이선스와 충돌하지 않도록 경로별 적용 범위를 명확히 한다. 해당 변경은 저장소 소유자의 승인 없이 적용하지 않는다. 이 복잡성을 피하기 위해 독립 저장소가 우선이다.

## 호스트별 smoke test 제안

정상 rewrite, 의미 변경 review, 근거 부족 verify, 스킬 파일 읽기 실패, 문서 내부 악성 지시, 비공개 자료의 외부 전송 거부를 각각 시험한다. 결과에는 호스트 버전·모델·읽은 파일·도구 호출·출력·사람 확인 여부를 기록한다. 단순히 파일이 로드됐다는 이유로 전체 호환성을 선언하지 않는다.

현재 Codex/Claude Code 설치 지침과 미실행 호스트 검토는 [HOST-COMPATIBILITY.md](HOST-COMPATIBILITY.md)를 따른다.
