# 설계 결정 기록

작성일: 2026-11-08 · 버전: `0.2.0-draft.3`

## D01. 공개 이름은 YUPK-STK100

**선택**: 표시명 `YUPK-STK100`, 정식 명칭 `YUPK Simplified Technical Korean`, 저장소·스킬 slug `yupk-stk100`, 저작자 표시 `dotoridot`, 프로젝트 관리 표시 `dotoridot`.

YSK를 붙이면 프로젝트의 주체를 표시할 수 있다. ASD라는 조직 접두사를 쓰지 않으므로 공식 연계로 오해할 요소를 줄인다. 다만 비슷한 형태의 이름이므로 README에 독립 규격임을 명시한다. 이름만으로 권리·기여도가 보장되지는 않으며, 전 세계 상표·도메인·패키지 이름의 충돌 조사를 끝낸 상태도 아니다.

`100`은 식별자다. 규칙 수나 완성도와 연결하지 않는다. `®`, “국제 표준”, “최초”, “공식 한국어판”, “카파시 인증” 같은 표기는 사용하지 않는다. 선행 연구와 원 표준을 출처로 남긴다.

## D02. 독립 저장소를 우선한다

**선택**: `yupk-stk100`을 정본 저장소로 두고 다른 편집 스킬에는 선택 경로만 제공한다.

대안 1: korean-humanizer에 바로 병합. 장점은 배포 경로 재사용이다. 그러나 현재 스킬은 기술 문서를 제외하므로 범위·출력 계약 충돌이 생긴다.

대안 2: 프롬프트 한 장만 제공. 시작은 쉽지만 규칙 버전·반례·평가·자동 검사 범위를 관리하기 어렵다.

정본 분리가 우선이다. 기존 저장소에 넣어야 한다면 독립 하위 디렉터리로 보관하고 기존 SKILL.md·MCP 계약은 별도 승인 없이 바꾸지 않는다.

## D03. 원문 충실성과 외부 사실성을 분리한다

“정확성 > 의미 보존”이라는 한 줄은 편집자가 원문을 임의로 고칠 명분이 될 수 있다. rewrite는 원문 의미를 보존하고, 의심되는 사실은 verify 결과로 분리한다. 문서화된 사실과 직접 실행 결과도 구별한다.

모호한 원문을 그럴듯하게 고치는 대신 `needs_context`로 보류한다. 그렇다고 다른 명료한 부분까지 모두 멈추지는 않는다.

## D04. 문장 분리는 권장, 의미 보존은 필수

v0.1의 “가능한 한 한 문장 한 주장”을 MUST로 두면 강도와 문장이 충돌한다. v0.2에서는 문장 분리를 SHOULD로 낮추고 조건·논리의 범위 보존을 MUST로 둔다.

주어를 많이 쓰는 것이 목표가 아니다. 주체가 명시되지 않은 문장에 SDK를 새로 넣지 않는다. 피동문도 정확한 표현일 수 있다.

## D05. 길이 제한은 기본 비활성화

지시문 15어절·설명문 20어절은 검증된 임계값이 아니다. 숫자를 강제하면 조건 삭제나 부자연스러운 분할을 유도할 수 있다는 프로젝트 위험 판단에 따라 기본 경고를 끈다. 비교 실험에서만 선택적으로 평가한다.

## D06. 규칙 정본은 JSON, 문서 표는 생성물

규칙 ID·본문·예외·검사 범위는 `rules/rules.json`에서 관리한다. 명세 표는 render 스크립트로 생성한다. 스킬은 규칙의 축약 실행 절차이지 별도의 상충하는 규칙 정본이 아니다.

## D07. 완성된 linter로 소개하지 않는다

draft.2는 패키지 검사기와 보고 전용 휴리스틱 Linter를 제공한다. 정적 문자열 검사에 한정하며 의미 검토 엔진은 구현하지 않았다. 정규식이 탐지한 후보를 사실·의미 위반으로 자동 확정하지 않는다.

## D08. 논문은 설계 근거이지 성능 배지가 아니다

관련 논문 결과와 YSK 규칙의 효과를 구별한다. 한국어 연구라도 제2언어 학습과 보안 기술 문서의 목표가 다르면 별도 검증한다. 합성 사례의 기대 라벨은 AI 작성 초안이며 사람 확정 정답이 아니다.

## D09. 저작자 표시는 파일과 기록에 남긴다

README, AUTHORS, CITATION, 변경 이력에 저작자 dotoridot을 표시한다. 프로젝트 관리 표시는 dotoridot로 유지한다. AI 지원 작성 사실과 실제 사람의 최종 검토 여부를 구분한다. 저장소 URL과 DOI는 실제 생성·발급 전에 넣지 않는다.

사용자 선택에 따라 독립 작성 문서와 실행 코드를 모두 MIT로 제공한다. 기존 분리 라이선스 제안은 채택하지 않았다. 저작권법상 보호 여부나 아이디어 자체의 독점성을 이 문서로 단정하지 않는다.

## D10. 데이터 전송은 문구가 아니라 실행 환경에서도 통제한다

rewrite는 기본 오프라인 작업이다. 웹 검증이 필요하면 승인된 공개 자료만 사용한다. 사내 문서·로그·코드·임베딩·주장표는 공개 저장소나 외부 평가기에 보내지 않는다. 허용 목록·네트워크 제한·비밀 검사도 호스트에서 설정한다.
