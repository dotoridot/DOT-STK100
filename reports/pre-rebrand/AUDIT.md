## 규칙 변경의 예, 반례와 예외

- K03 좋은 예: 서버만 삭제 -> 삭제 주체는 서버뿐. 나쁜 예: 서버도 삭제. 모호성: 은/는의 대조 여부는 앞 문맥에 의존한다. 예외: 단순 조사 통일을 전역 강제하지 않는다.
- M08 좋은 예: 추정은 추정으로 유지하고 확인된 사실 수정은 요청 범위와 근거를 표시. 나쁜 예: rewrite에서 추정을 확정으로 교체. 모호성: 오류인지 문맥 부족인지 미확인. 예외: 사용자가 사실 수정까지 요청했으면 이미 허용된 범위를 수행한다.
- M06 기존 규칙 반례: 할 수 있다 -> 발생 가능성이 있다. 능력/허용/가능성을 구별할 근거가 없으면 needs_context다.
- 자동 검사 반례: 각각 같은 값의 압축은 숫자 횟수 경고를 만들 수 있고, 주체 이름 교환은 값을 유지해 미탐할 수 있다. 경고 없음도 합격이 아니다.

## 원격 상태와 승인 대기

이 폴더는 작업 시작 시 Git 저장소가 아니었다. 저장소 생성, 원격 URL 설정, 커밋, Push, PR, 공개, 태그, 릴리스를 수행하지 않았다. 후속 공개 대상은 독립 ysk-stk100이다. 소유자/공개 여부/브랜치/라이선스 채택과 원격 변경은 별도 승인 후 진행한다.

현재 산출물은 검토 가능한 로컬 초안과 도구다. 구조 테스트와 개발 사례 집계만으로 규격의 기술적 정확성 또는 의미 보존 성능이 입증됐다고 주장하지 않는다.
